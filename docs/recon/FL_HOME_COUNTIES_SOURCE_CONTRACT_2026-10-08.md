Scope: Lee, Collier, Charlotte, Manatee, Hendry, Glades and DeSoto. These are the home-market counties in Bond Product Gaps top-10 item 9. All checks ran from the agent box between about 7:58 and 8:07 AM ET. Each used plain HTTPS with an honest User-Agent (`ShamrockBailBonds-SourceCheck/1.0`), with no proxy, no cookies beyond the site's own session, no impersonation and no CAPTCHA. Only field names, counts and digit-masked key shapes were recorded. No names, DOBs, addresses or booking numbers are in this repo.

## What `recon_only` means and what moves a county out

`docs/recon/COUNTY_SOURCE_CONTRACT_MATRIX.md` is generated by `scripts/build_recon_matrix.py`:

- `verified_public` and `fail_closed` are copied from `SCRAPER_SOURCE_STATES` (Health). Nothing in this doc changes either.
- Otherwise the row's `passive_recommendation` in `county_source_contract_evidence.json` decides. `productive` becomes **`candidate_productive`**, and `recon_only` stays `recon_only`.
- Under the matrix operating rule, a row leaves `recon_only` only after a county-specific validation records the official listing URL, the complete public name, a source-issued booking identifier, the booking or arrest date/time, permitted pagination, and no access-control workaround. That is what this doc records.
- `candidate_productive` does **not** change Health. Every one of these counties stays `unverified` in Health. `verified_public` needs a Leads Ops write smoke, which now goes in `docs/recon/smoke_evidence.json` (below).

## Evidence slot: `docs/recon/smoke_evidence.json`

One row per requested or recorded smoke. `scripts/build_recon_matrix.py` validates the file and renders it as **Write smoke and relay evidence** in the matrix.

| Field | `requested` | `passed` / `failed` |
|---|---|---|
| `label`, `kind` (`write_smoke` / `relay_read` / `relay_write`), `requested_on`, `command`, `expect`, `source` | required | required |
| `blocked_on` | optional | optional |
| `run_on` (YYYY-MM-DD, ET), `commit` (git SHA the run used), `egress` (`vps` / `mac` / `residential_relay`), `method` (`one_shot_run` / `relay_only_run` / `relay_read_smoke` / `prod_mongo_aggregate`), `result` | must be absent | required |

The builder refuses:
- relay rows for a county that is not in `config/relay_only.py`, or relay rows from any egress other than `residential_relay`;
- a passed write without `result.status: ok`, `result.mongo_writer_results >= 1` and `new_records + updated_records >= 1` (a run with no `MONGODB_URI` reports `new_records` with no writer and does not count);
- a passed `relay_read` without `result.columns` and `bookings >= 1`;
- a passed write on a `fail_closed` county;
- a county listed in the file that is `verified_public` in Health with no passed write.
